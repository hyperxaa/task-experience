# Arquitectura / Architecture

## ES

**Una app, dos builds.** `app/` contiene la interfaz React; `app/api/xp/route.ts` delega en `lib/server.ts`; `lib/domain.ts`, `lib/weekly-bonuses.ts`, `lib/cycles.ts` y `lib/discoveries.ts` contienen las reglas comunes. `db/schema.ts` y `drizzle/` definen el esquema y las migraciones. Next compila para Node; Vinext/Vite compila el mismo código para Workers. Vite sustituye `db/platform.ts` por `db/sites.ts` y `lib/runtime-config.ts` por `lib/runtime-config.sites.ts`; el bundle Workers no incorpora `better-sqlite3`.

**Petición:** navegador → `/api/xp` → comprobación de origen, sesión y rol → acción validada del dominio → escritura condicional por `revision` → SQLite o D1 → estado filtrado para el perfil. `requestId` evita abonar dos veces una acción repetida. El adaptador ofrece consultas preparadas y `batch`: transacción de `better-sqlite3` en Node y lote atómico nativo en D1.

**Acceso:** el primer alta requiere `TASK_XP_SETUP_TOKEN` en producción y crea una contraseña familiar; después cada persona entra con cuatro animales en orden. El rol adulto/hijo se guarda con el miembro, sin depender del nombre ni género. Argon2id portable protege contraseña y códigos con un `SESSION_SECRET` adicional. La sesión dura 12 horas; «recordar dispositivo» usa un token separado, rotativo y revocable hasta un año. Las cookies son HttpOnly y SameSite=Strict; los tokens aleatorios solo se guardan como SHA-256. La combinación inicial puede mostrarse una vez más tras el primer login familiar: hasta entonces permanece cifrada y luego se elimina. Los cambios de seguridad revocan otras sesiones. El servidor aplica límite de intentos, y las acciones parentales vuelven a exigir el perfil adulto.

**Xp:** las misiones guardan Xp, calendario, repeticiones y destinatarios. Al completarlas se crea un registro con la puntuación acordada entonces; editar o archivar la misión no borra ese historial. Un plan semanal congela las misiones existentes y permite nuevas misiones desde su fecha de alta. Una misión perfecta obtiene Xp base + bonus equivalente (×2); toda la semana perfecta lleva las misiones a ×5 total y sustituye el ×2. Los descubrimientos y misiones únicas quedan fuera de ese multiplicador. Canjes restan saldo, no experiencia histórica; cancelarlos devuelve saldo. Los ciclos de progreso son configurables y no cambian la semana de bonus de lunes a domingo. Fechas según `Europe/Madrid`.

**Datos:** modo demo crea Xavi, Mireia, Aina e Iara con sus misiones iniciales y saldo vacío. Modo personalizado acepta de 2 a 12 miembros, al menos un adulto y un hijo, nombres distintos y cualquier composición familiar. Los miembros se fijan en el alta; editar la composición después requiere una migración específica. El JSON exportado contiene progreso, pero no contraseña, códigos, sesiones ni dispositivos. Solo se importa en una instalación con los mismos miembros. Linux y Sites no sincronizan datos automáticamente.

## EN

**One app, two builds.** React UI lives in `app/`; `/api/xp` delegates to `lib/server.ts`; `lib/domain.ts`, `lib/weekly-bonuses.ts`, `lib/cycles.ts` and `lib/discoveries.ts` hold shared rules. `db/schema.ts` and `drizzle/` hold the schema and migrations. Next builds for Node; Vinext/Vite builds the same app for Workers, replacing the database and runtime configuration adapters at build time.

**Request flow:** browser → `/api/xp` → origin, session and role checks → validated domain action → conditional write using `revision` → SQLite or D1 → profile-filtered state. `requestId` prevents double credit on retries. Prepared queries and atomic batches run through `better-sqlite3` transactions or D1's native batch.

**Authentication:** production setup needs a separate setup token. A family password unlocks the device, then each member enters a unique four-animal code. Adult permissions come from stored roles. Portable Argon2id plus a stable server secret protect password and codes. Sessions last 12 hours; a separate rotating, revocable remembered-device token lasts up to one year. Cookies are HttpOnly and SameSite=Strict, while storage holds only token hashes. Pending animal codes are encrypted until the first successful family login. Security changes revoke other sessions and failed attempts are limited.

**Xp and data:** scheduled completions preserve their awarded Xp even when a mission changes. A perfect mission earns ×2 total; a perfect week earns ×5 total instead of ×2. Rewards spend balance without erasing earned experience. Bonus weeks are Monday–Sunday in Madrid time, independently of the configurable progress cycle. Demo mode supplies the four preset family members and missions with no past activity; custom mode accepts 2–12 distinct members including at least one adult and child. Members are fixed after setup. JSON progress exports exclude credentials and require the same members on import. The two deployments never synchronize automatically.
